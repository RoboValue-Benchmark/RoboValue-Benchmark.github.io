# 评测申请后端与前端对接

这组文档记录 RoboValue 评测申请的实际设计、实现边界和复用方法。整理日期：2026-10-21；运行行为以 CloudBase v4.1 源码及最近一次验收记录为依据。它不是实时账单或在线可用性监控。

## 阅读顺序

1. [设计与数据流](design.md)：为什么这样拆分、申请如何保存、前端如何判断结果，以及邮件、积压、限额和告警如何工作。
2. [管理、验收与复用](operations.md)：在哪里查看申请、如何排查、如何安全修改配置、哪些内容可以复用，以及部署收尾。

## 当前方案

网站继续由 GitHub Pages 托管，保留原有填写入口。浏览器调用 Tencent CloudBase 原生云函数接口；后端将申请保存到私有文档数据库，再由私有定时任务发送管理员通知。没有购买自定义域名，也没有内嵌第三方表单。

| 职责 | 实现 |
| --- | --- |
| 表单与提交状态 | `src/eval.jsx`、`src/eval-status.mjs` |
| 请求、回执检查与重复提交标识 | `src/eval-transport.mjs`、`src/eval-request.mjs` |
| 云端适配与启停开关 | `server/cloudbase/runtime.mjs`、`index.cjs` |
| 校验与提交入口 | `server/cloudbase/submit.mjs`、`server/evaluation-applications.mjs` 中的 `validateApplication` |
| 数据事务、限额、通知认领与状态 | `server/cloudbase/document-store.mjs` |
| 申请通知、积压提示与运行告警 | `server/cloudbase/notify.mjs` |
| 生产构建约束 | `vite.config.js`、`eval-public-config.json` |

部署源码与版本化操作脚本目前保存在维护者工作区；下表中的部署路径用于对应实现，并不表示本次网页发布会公开所有后端部署文件。

## 已验收与尚未确认的区别

- 已验收：真实页面提交、数据库保存及字段回读、同一申请重试回执、定时发送及 `sent` 状态写回、私有权限、前端各状态和手机排版。
- v4.1 修复了告警发送期间晚到异常可能漏报的问题；当时完整回归测试共 123 项通过。这不是 123 项线上压力测试。
- 当前团队收件箱是否实际收到最新邮件，不能仅由 SMTP 接受及 `sent` 状态推断；此前个人测试收件箱曾由用户确认收到。
- 没有验收独立于 CloudBase 的外部故障告警、验证码或 WAF，也没有测定实际最大吞吐量。
- 最后一次验收确认关闭超额按量和自动续费；这些是有时间点的检查结果，后续应以控制台实际配置为准。

这组文档不保存管理凭证、SMTP 授权码、IP 哈希密钥、真实申请内容或授权会话。部署证据及敏感备份不应复制到公开仓库。
