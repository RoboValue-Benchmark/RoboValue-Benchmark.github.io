# 管理、验收与复用

先读[设计与数据流](design.md)。本页是操作说明，不会自动执行任何云端更改。

## 1. 查看、查找和导出申请

1. 登录 [Tencent CloudBase 控制台](https://tcb.cloud.tencent.com/dev)，使用有权管理目标环境的腾讯云账号。
2. 选择环境 `robovalue-eval`（核对完整环境 ID `robovalue-eval-d6gvbrl7g1fa30d73`，上海）。
3. 打开数据库中的文档型数据库，进入 `evaluation_applications` 集合。具体导航名称可能随控制台版本调整。
4. 展开 `application`，查看 `submittedAt`、团队、机构、模型、邮箱和已填写联系方式；展开 `notification` 查看通知状态。
5. 用邮件里的 Application ID 精确查找 `_id` 或 `applicationId`。按团队或时间排查时，新结构字段路径分别为 `application.teamName`、`application.submittedAt`。
6. 需要离线处理时使用集合导出功能，将导出文件保存到受控位置；不要提交到 Git、网站静态目录或公共网盘。

UTC ISO 时间末尾 `Z` 表示 UTC；与北京时间相差八小时。邮件已转换为北京时间，并明确写出 UTC+8。旧测试记录的时间可能仍在根级 `submittedAt`，不要误认作新记录缺失时间。

目前没有人工“审核状态”。`notification.status = sent` 只用于发信执行，不能用它判断团队是否已联系申请人。阅读或导出不会自动改变通知状态。

## 2. 常见问题如何判断

| 现象 | 先检查什么 | 不要做什么 |
| --- | --- | --- |
| 用户看到成功页 | 在正式 CloudBase 模式下，代表浏览器验证了保存回执；可按编号查记录 | 不把本地 preview 模式成功页当作真实保存 |
| 用户超时或断网 | 表单不变时先按原编号重试；管理员再查保存记录 | 不断换编号重复提交；不直接断言保存失败 |
| 有申请、没邮件 | `notification.status`、`nextAttemptAt`、所属窗口、定时器、通知函数开关及 SMTP 配置 | 不删除申请来重试；不把 `pending` 当成数据丢失 |
| `sending` 长时间未结束 | 看 `leaseUntil` 是否到期，后续调度是否运行 | 不让旧执行者任意覆盖租约；不猜测邮件一定没发出 |
| `sent`、收件人说没收到 | 垃圾邮件、目标收件地址、SMTP 接受后的投递情况 | 不把 `sent` 当作收件箱证明 |
| `failed` | `attempts`、`errorCode`、`failedAt`；修好原因后制定受控重发 | 不直接改为 `sent`；不批量清空尝试计数掩盖故障 |
| 灰色倒计时 | 看业务 `limitType` 及恢复时间；正常申请共用 IP 也可能触发 | 不认为一定是恶意用户；不将平台所有 429 都映射成业务限额 |
| 整个服务不可用 | 环境有效期、额度、函数状态、开关、权限、安全域名和公网请求 | 不仅凭未收到告警判断健康；不先打开超额或放宽数据库权限 |

运行事件在 `evaluation_rate_limits` 的 `alert_` 记录中。`window_` 是申请通知计数，`ip_`/`global` 是限额数据，`notification_dispatch` 是调度认领；它们不是人工管理字段。

## 3. 安全修改配置

### 收件邮箱

通知函数的 `EVAL_NOTIFY_TO` 控制唯一固定收件地址。更换应由管理员修改配置，先用合成申请验证 SMTP 接受，再由新收件人确认收件箱；不要把收件地址从表单传入后端。

更换只影响后续执行读取到的配置，已送达旧邮箱的副本不会消失。不要认为改邮箱会自动重新发送全部 `sent` 记录。当前发件账号及授权码属于服务端配置，不应进入截图、命令参数、构建日志或公开文档。

### 临时停用

- 提交开关 `EVAL_SUBMISSIONS_ENABLED` 不为字符串 `true` 时，函数返回 `NOT_ENABLED`，不进行保存；前端提示暂不可用。
- 通知开关 `EVAL_NOTIFICATIONS_ENABLED` 不为 `true` 时，通知任务不发信；已保存的待通知申请不会因此删除。
- 平台停用、额度用尽、权限变更或网络故障可能在到达业务代码前失败，前端通常显示“结果未确认”，不保证拿到 `NOT_ENABLED`。
- 修改开关不等于取消套餐、续费或其他产品；关闭超额按量也不等于关闭正常业务。

### 费用和容量

最近验收确认该环境为个人版预付费，超额按量关闭、自动续费关闭，到期时间为 2026-11-20 23:59:59。此前购买页面显示优惠价 19.90 元/月；后续续费价格以实际订单为准，不能将优惠价当永久承诺。

套餐资源点由函数、数据库等服务共享消耗，不是独立的“可保存多少份表单”。当前没有测定剩余空间、每份申请完整费用或最大并发容量，不应从应用限额或套餐宣传 QPS 推导真实承载量。

正常提交、被拒绝的请求、通知、告警、重试和后台查询均可能消耗资源。关闭超额后，额度耗尽可能造成暂停；要持续查看用量。其他腾讯云产品和历史延迟出账独立核查，不能以本环境配置推断全账号费用。

此前旧广州 SCF/COS 资源已有独立退役验收；本轮文档、网页预览不再创建或恢复它们。免费的资源包不代表持有的其他资源没有用量收费；资源是否还存在和账单是否结清是两件事。

### 数据保留与清理

当前自动清理只处理过期的 `ip_` 限额计数，每轮最多检查 20 条，有工作时间预算。它会在事务中重查，避免删除刚被新请求续用的计数。

申请本身、窗口摘要、告警记录没有在这里配置自动到期删除。旧测试记录仍保留。需要清理时先导出、明确保留期限与范围，再做独立操作；不要擅自删除仍有待通知记录的窗口或重置全站配额。

## 4. 修改代码后的验收顺序

### 本地验证

使用 Node.js 20.19 或更新的兼容版本；CloudShell 自带旧版本不一定满足要求。先确认 `node --version`，再运行：

```bash
npm ci
npm run test:eval
npm run build
```

构建检查与测试并不连接云资源。不要为普通前端样式改动重新部署后端。需要验证页面时，用本地浏览器拦截云请求生成模拟回执和错误，检查桌面、手机、深色模式、重复点击、加载状态、未知响应及配额恢复。

本地开发默认 `preview` 模式只显示成功效果，不发请求、不保存、不发邮件。正式构建由 `vite.config.js` 固定使用 `cloudbase`，公开配置缺失或不合规会停止构建；不会静默退回“假成功”。

### 云端发布与验收

1. 只读检查账号、环境、现有配置、代码版本、权限、数据库规则、索引、计费开关及定时器，保存脱敏快照。
2. 离线打包、锁定依赖、记录 ZIP 哈希；确认文件列表不包含凭证、真实申请或本地状态文件。
3. 先准备私有资源和禁止普通客户端访问的权限。代码更新时按具体版本制定受控步骤；需要暂停通知时先暂停并等待在途任务，保持提交能力的边界清楚。
4. 更新目标函数并等待 Active，回读代码哈希、入口、配置和权限。不能仅凭 API 返回“已接受”视为成功。
5. 使用合成数据做一次真实提交，核对数据库全部字段及服务器时间；同一编号重试必须返回原回执，不新增申请。
6. 验证可信 IP 来源、缺失来源拒绝、普通客户端无法读写数据库或调用通知函数，以及通知租约、幂等和窗口归属。
7. 等实际定时器执行，检查 SMTP 接受和数据库状态，再请收件人确认收件箱。三者分别记录，不能相互替代。
8. 核对网站实际发布版本和请求方式，保留验收证据，明确仍未确认的事项。

历史部署脚本带账号、环境、哈希和旧版本前置条件，属于特定发布操作，不是可盲目重跑的一键安装器。v4.1 之后不能直接重跑只接受 v4 的旧发布脚本。SDK 响应不明或超时有可能已产生部分更改，应先只读回查，避免重复创建或自动回滚破坏已有状态。

## 5. 怎样复用这个方法

可以复用的是职责和协议，不是当前账号的环境值：

1. 保留“前端 → 最小权限提交入口 → 事务数据库 → 私有 outbox worker”的分工。
2. 定义字段白名单、长度、服务器时间、幂等编号及明确保存回执，再实现页面状态。
3. 将保存申请、待通知状态和配额计数放在同一事务；通知采用租约认领与条件写回。
4. SMTP 不支持跨数据库的恰好一次投递，要允许可识别重复，并保留失败申请。
5. 选择与真实需求匹配的窗口、批量、重试和限额；不要把当前数值照搬成性能保证。
6. 将公开 Publishable Key 与管理员凭证分开。修改环境时也要同步权限、索引、安全域名、固定收件地址、邮件后台入口、构建约束和验收脚本。
7. 用模拟依赖测试故障与竞争条件，再做最小规模的云端验收；不要通过大量线上提交做普通 UI 测试。

这里的 runtime 目前限制地域为上海，生产构建也校验明确环境 ID；更换环境或地域不是只改一个字符串。邮件中的后台环境别名也需同步。保留这些显式检查能避免操作错账号，但复用时必须逐项调整并重新验收。

## 6. 操作过程与收尾安全

- 授权只通过官方入口完成，不索取或粘贴密码、SecretKey 或 SMTP 授权码。只使用本次任务所需权限。
- 不把凭证放入命令行、Git、公开构建、图片或随意打印的 SDK 响应。必要的私有状态目录与文件分别使用 0700、0600。
- 不将生产记录复制到预览；测试使用明确标记的合成数据。
- 操作完成后核对业务开关、权限、定时器、计费、旧资源状态和后台版本，再退出本地官方 CLI 会话，清除本次敏感临时备份。
- 最近一次收尾确认官方 logout 成功、本地认证文件不存在；这不等于已核实所有远程授权被撤销，也不影响已部署业务继续运行。
- 不删除仍运行环境依赖的服务角色，不为“清理”而重置未知权限；无法确认的资源或账单状态必须明确记录。
